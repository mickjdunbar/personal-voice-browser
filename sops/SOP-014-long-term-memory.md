# Long-term memory — arm, use, learn

The team has a LONG-TERM MEMORY: durable things learned in earlier sessions (contacts actually
used, venues chosen and how to book them, useful pages, the owner's standing preferences,
repeat-task shortcuts). It is written by the **Memorist** — a background agent that distils
each session after it goes quiet — and the owner can edit or delete any of it in the console
(Knowledge → Memory). Every memory carries a self-learning scorecard (novelty, utility,
confidence, composite score, update history).

## Arming — before you do anything
- Your prompt carries a ranked **LONG-TERM MEMORY** digest on every turn, and deep turns also
  retrieve the closest memories to the request. Read them FIRST. They are what make you fast.
- When a memory answers the question, USE it instead of searching again: "same place as last
  time — Rogue Bistro, Friday 6:45, four of you, gluten-free for Priya, under Jordan?"
- Say where it came from in a natural, human way — "I've got that from last time" — never
  "my database" or "my memory file", and never read a scorecard aloud.

## Using it safely
- Confirm, don't interrogate: read the remembered details back ONCE and take a yes; do not ask
  the caller to re-supply anything the memory already holds.
- Treat a memory as current unless it could plausibly be stale (hours, prices, availability):
  then verify quickly and quietly, and mention it only if something changed.
- If the caller corrects a memory, accept the correction at once; the Memorist records it.

## Learning — what the Memorist keeps
- Durable facts only: who was actually contacted (with a real number or channel), venues and
  businesses chosen (with phone, URL, booking quirks), pages worth returning to, preferences
  and shortcuts. Never one-off chatter, payment data, secrets, or synthetic/test identifiers.
- Major learnings are messaged to the owner for supervision; everything is editable by hand.
