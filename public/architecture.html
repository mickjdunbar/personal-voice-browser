Personal Voice Browser — how it works

One call — phone or browser — a team of AI agents, a shared screen, and work that keeps going after you hang up

Download PDFOpen the console

The Personal Voice Browser is an assistant you talk to — ring its phone number, or press the orb in your browser. The voice that answers (Aria) chats like a mate, and behind her a small team of specialist agents works out what needs doing, browses the real web, phones people and businesses, talks to other chatbots, texts and WhatsApps you, mirrors every page onto a screen you can watch, keeps working after you hang up, and remembers what it learned for next time.

Why it matters — reaching the world's AI agents without integrations built in advance

Every service is putting an AI agent on its front door: a voice agent on the phone line, a chatbot on the website, a booking form, a text line. There will soon be far more of them than anyone could wire up with APIs or MCP connectors at build time — and most of them will never publish one. An assistant that can only use integrations it was given before runtime will be stuck.

The idea the Personal Voice Browser demonstrates: give the assistant the same channels a person has — the web, the phone, chat windows, text — and let it reason at runtime about which interactions a job needs and discover the channel each counterpart actually exposes: a web page to read, a form to fill, a phone number to ring (and a human, a phone menu, or another AI on the other end), a chat widget to ask, a mobile to text. If a proper integration exists (a calendar via Zapier/MCP) it uses that; if not, it converses the way a person would — and brings the result back.

So the same assistant can deal with a restaurant whose only interface is a booking page and a phone line, a bank whose front door is a voice agent, and a courier with a webchat — none of which were integrated in advance. The call-inside-a-call in these showcases is exactly that: Aria rings a number read off a web page and finds another AI (Sunny, a receptionist agent) answering — and simply talks to it.

Process flow — one real example, step by step

Compare two places, book the better one, confirm it with them, put it in my calendar, text the others the meeting point, and work out the walk from the bar — message me that later." Architecture

  • Two ways in, one brain — a real PSTN number on Twilio feeds a SIP trunk into jambonz; the console's orb places a WebRTC call straight into jambonz with the official client. Both land on the same harness session, so the voice and the screen are one experience either way. Huey dials the phone number to automate testing.
  • The harness is a Node service: the conductor runs Aria on OpenAI's speech-to-speech model so the voice is fast and natural, and hands anything that needs doing to the agent team — a deep-reasoning model with browser, phone, chat, text and MCP tools, and specialists (Lumi for local and weather, Remy for shopping and orders, Sage for research, Nova as the web generalist). The caller only ever hears Aria; the specialists work behind her.
  • The screen — the Personal Voice Browser console shows the live browser frames, the tabs, the pins and what each agent is doing. You can take control of the page yourself and hand it back.
  • Knowledge — SOPs (how the team behaves), FAQs (what it knows) and Memory (what it has learned) are markdown files indexed in Qdrant and editable in the console.
  • Channels out — any web page, phone line (jambonz places the call in Aria's voice), chat widget or text; MCP/Zapier when an integration exists; a Tasks channel to WhatsApp and SMS through Twilio. Everything is captured into a shareable recap like this one.

Long-running tasks and long-term memory, in a little more depth

Long-running tasks. Aria can start a background task from the call in one breath ("underway — I'll WhatsApp you"), or you can start one by messaging the Tasks channel. Each task is a thread with its own browser tab, worked off the call by the same team with a bigger research budget; replies, screenshots and sketches land in the thread and are forwarded to WhatsApp. Replying on WhatsApp ("#8 make it 6pm") continues that thread. Tasks survive the call ending and the server restarting.

Long-term memory. The Memorist watches each session and, once it goes quiet, extracts up to three durable learnings, scores them on novelty, utility and confidence, merges refinements into existing memories, and messages you the notable ones. Every session starts armed with the ranked digest, and the deep lane retrieves matching memories per turn. Memories are plain markdown with a metadata block — version, created and edited timestamps, who changed it, how often it was used — and can be edited or deleted in the console. SOPs and FAQs sit beside them in the same Knowledge drawer.

How it was tested — synthetic callers over the telephone

The browser call works today, but for testing we wanted the hardest path and something repeatable: so Huey (an AI-agent testing platform) plays the caller over the public telephone network. A persona — Jordan Blake, a Brisbane operations manager organising a team dinner — dials the real PSTN number through Huey's jambonz runner, follows a scripted brief with natural improvisation, holds when told to, and hangs up only on a scripted goodbye. Each test segment carries compliance policies (for example "pin shown on the Personal Voice Browser", "delegation announced", "hold etiquette", "no premature hang-up") that a monitor scores from the transcript, and every take produces a recap like this one automatically. That turns a demo into a regression suite: a take is re-run after every fix.

Outbound calls Aria places during a test are redirected to Sunny, Huey's own voice agent, so the call-inside-a-call is machine to machine over the PSTN and nobody real is rung. A launcher checks the server, the tunnel, the redirect and the WhatsApp window before dispatching, then prints the per-policy result, the transcript and the recap link.

Sharing the browser — the same session by phone or in your browser

The harness owns a headless Chromium browser per session. Every frame of the active tab is streamed over a WebSocket to the Personal Voice Browser web page, along with the tab strip, the activity overlay ("Searching…", "Dropping a pin…"), lists of options as cards, and pins as a map badge. The caller can click, scroll and type on that frame — the harness forwards the input to the real page and hands control back to the team when they say so. A screenshot of each page visited is kept for the recap.

Because the screen is a web page and jambonz speaks WebRTC, the browser call already exists: open the console, press the orb, and the voice and the screen are in one window with no phone number involved — the official jambonz web client dials the same application the phone number routes to. The phone path exists so that anyone, on any phone, can ring it, and so that Huey's synthetic callers can exercise the whole telephony chain. In practice a product would offer both: a link for people at a screen, a number for everyone else.

How this differs from the personal AI agents — Meta Muse and Instinct

In the week this page was written (13 Nov 2026) both of the headline personal agents gained the ability to phone businesses: Meta Muse (10M+ users; calling went live on 12 Nov for paid US subscribers, US businesses only, after an internal test in September that turned out to be routed to human contractors) and Instinct (Concierge, launched 16 Sep; invite-only, US calls only, the agent reports back and will not commit without approval). Both browse the web on your behalf from a cloud machine; Muse also books flights through Duffel and hotels through Agoda in Singapore and Japan. Neither is available in Australia. They are the right thing to compare against, because they are what people will have in mind when they see this demo.

The short version: Muse and Instinct are apps that have added a phone. The Personal Voice Browser is a phone call that has a team, a screen and the web behind it — built on open telephony, governed by editable procedures, testable with synthetic callers, and deployable inside someone else's perimeter. Points for Dave Horton / jambonz.

  • The phone is becoming the universal API for agents. Muse and Instinct both reached for outbound calling within weeks of each other because the web alone cannot finish an errand. Every personal agent will need a calling substrate; this harness shows jambonz is already that substrate — SIP, WebRTC, S2S bridge, outbound-inside-inbound, dub tracks — with no product work on the agent side.
  • AI ↔ AI over the PSTN is real now. Aria calling Sunny is a jambonz app calling a jambonz app. The interesting traffic on carrier networks in 2027 is agents ringing the AI front doors of businesses; the custom-harness protocol is a natural place for a well-known descriptor so a calling agent can discover that a number is answered by an AI and negotiate accordingly.
  • One session, two transports. The orb uses the official jambonz web client to dial the same application the number routes to, so voice and screen are one WebSocket-fed experience. That is a story Meta cannot tell: their screen is a VM, not the call.
  • Synthetic callers over the real network turn telephony demos into regression suites. Huey dialling the number through its own jambonz runner is a pattern any jambonz customer could adopt.

Points for the VERSA SLT.

  • Clients' contact centres are about to receive calls from these agents. Muse is US-only today and "coming weeks" for Australia according to Meta's own account. A member's agent ringing a fund, a bank or an insurer is the inbound side of exactly what this harness does outbound — and it shows what a discoverable, well-behaved AI front door needs to look like (clear identity, structured answers, no dead air).
  • An enterprise cannot run its agent on Meta's VM. The capabilities regulated clients will ask for — SOPs a compliance team can read and edit, read-back before money moves, audit of every turn, synthetic-caller regression, data staying in the client's perimeter — are built into this harness and absent or opaque in the consumer agents. That is the consulting proposition: the same end-to-end agency, governed.
  • Works in Australia now, on a real Brisbane number, with Australian businesses on the other end. The consumer agents' calling features are US-only and gated behind paid or invite tiers.
  • Voice plus screen is a better member experience than text plus transcript. A map, a comparison or a form is shown while the member talks; the member can take over the page to sign in or choose, then hand back. Pair that with a healthcheck-style evaluation and it is a credible reference architecture, not a prototype pitch.

Where the consumer agents are ahead, to be fair. Scale (Muse claims 10M+ users), payments and purchasing, email and calendar inside the product, persistent cloud desktops per user, partner booking rails (Duffel, Agoda, Expedia), and a consumer brand. The Personal Voice Browser is a one-owner prototype that proves the pattern; it is not yet multi-tenant, has no payment hand-off, and its specialists are role descriptions rather than trained verticals. The comparison is about architecture and governance, not polish.

Where it could go next

  • Channel discovery at scale — a directory or well-known descriptor so an assistant can find a service's AI front door (phone, chat, agent endpoint) without a search, while still falling back to conversation when none exists.
  • Caller identity — knowing who is ringing (number, profile) so "text me", contacts and memory are per person rather than per owner.
  • Richer screen widgets — forms the caller fills on screen, map pin-drops they place themselves (the xApp path already exists), payment hand-off.
  • More specialists and tools — travel, calendar-first planning, email triage — each a short role description plus the sites they own.
  • Memory governance — approval before a memory is used, expiry, per-caller scopes.
  • Scale — one harness serves one owner today; sessions, tasks and memory are already keyed, so multi-tenant is a configuration step rather than a redesign.
